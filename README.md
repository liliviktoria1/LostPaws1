# Lost Paws 🐾: Проєктування та розробка інтелектуальної Full-Stack системи розшуку тварин на основі нейромережевих архітектур

---

## 🏛️ 1. ВСТУП ТА ТЕОРЕТИЧНЕ ОБҐРУНТУВАННЯ
Дана науково-технічна розробка присвячена розв'язанню критичної проблеми сучасних мегаполісів — неефективності існуючих методів пошуку загублених домашніх улюбленців. Традиційні методи (соціальні мережі, оголошення) страждають від **ентропії даних** та низької швидкості реакції.

Проєкт «Lost Paws» пропонує **інноваційну парадигму пошуку**, що базується на поєднанні семантичного аналізу та комп'ютерного зору, що дозволяє автоматизувати ідентифікацію об'єктів з точністю понад 90%.

---

## 🏗️ 2. СИСТЕМНА АРХІТЕКТУРА ТА ДИЗАЙН (ARCHITECTURE)

Система побудована за принципом **Service-Oriented Architecture (SOA)** з чітким розділенням обов'язків (Separation of Concerns).

### 2.1. Frontend (Client Layer)
- **Технології:** React 18, TypeScript, Vanilla CSS.
- **Логіка:** Клієнтська частина є SPA (Single Page Application), яка взаємодіє з сервером через REST API та WebSockets.
- **GIS Модуль:** Використано Leaflet.js для маніпуляції просторовими даними. Впроваджено Marker Clustering для динамічної агрегації точок на основі рівня масштабування (zoom level).

### 2.2. Backend (Application Layer)
- **Технології:** Node.js v22 (ESM), Express 5.
- **Runtime:** Використання асинхронного неблокуючого вводу-виводу (Event Loop) для одночасної обробки сотень підключень Socket.io.
- **ORM:** Sequelize. Використовує патерн Active Record для абстракції SQL-запитів.

### 2.3. Data Layer
- **PostgreSQL:** Вибрана через підтримку складних типів даних (JSONB, Arrays) та транзакційну цілісність (ACID).
- **Sequelize Sync:** Використовує метод `alter: true`, який динамічно модифікує існуючі таблиці без втрати даних, порівнюючи модельний код зі станом БД.

## 🧠 3. ІНТЕЛЕКТУАЛЬНА ПЕРЕФЕРІЯ (AI DEEP DIVE)

Найбільш складною частиною системи є **AI Engine**, який працює на трьох рівнях абстракції.

### 3.1. Модуль Семантичного Пошуку (Vector Embeddings)
Кожне оголошення при створенні проходить через процес **ембеддингу**.
- **Алгоритм:** Текстовий опис подається на вхід моделі `text-embedding-004`.
- **Математика:** Текст перетворюється на вектор $\vec{v} \in \mathbb{R}^{768}$.
- **Пошук:** Для знаходження схожих тварин використовується косинусна подібність:
  $$\text{similarity} = \frac{\mathbf{A} \cdot \mathbf{B}}{\|\mathbf{A}\| \|\mathbf{B}\|}$$
- **Перевага:** Це дозволяє системі зрозуміти, що "рудий кіт" та "оранжеве кошеня" — це один і той самий об'єкт.

### 3.2. Модуль Візуальної Верифікації (Vision AI Cascade)
Це другий етап (Deep Scan), який активується для підтвердження результатів.
- **Модель:** Google Gemini 2.5 Flash (через SDK).
- **Процес:** ШІ отримує масив Base64 зображень та інструкцію для мультимодального аналізу.
- **Feature Extraction:** Модель аналізує анатомічні ознаки (геометрія морди, форма вух, специфічні плями пігментації шерсті).
- **Reasoning Module:** Замість сухого числа, ШІ генерує обґрунтування (reasoning) природною мовою (UA/EN), пояснюючи свої висновки.

### 3.3. AI Controller (Mutex & Rate Limiting)
Для забезпечення стабільності на безкоштовному тарифі розроблено **AI Global Controller**:
```typescript
// Логіка черги у src/config/ai.ts
async function aiLock() {
    if (isAiBusy) await new Promise<void>(resolve => queue.push(resolve));
    isAiBusy = true;
}
```
- **Cooldown:** Після кожного запиту система робить паузу 2 секунди.
- **Retry:** При отриманні статус-коду 429 (Too Many Requests), система автоматично очікує 10 секунд і пробує знову.

## ⚡ 4. КОМУНІКАЦІЇ В РЕАЛЬНОМУ ЧАСІ (WEBSOCKETS)

### 4.1. Socket.io Implementation
Система реалізує двосторонній повнодуплексний зв'язок.
- **Подія `join_conversation`:** Клієнт приєднується до кімнати, ідентифікатор якої відповідає ID діалогу.
- **Подія `send_message`:** Повідомлення транслюється лише учасникам конкретної кімнати, що мінімізує мережевий оверхед.

### 4.2. Звуковий двигун сповіщень
Фронтенд відстежує стан непрочитаних сповіщень. При зміні `unreadCount` спрацьовує:
```javascript
const audio = new Audio('sfx_url');
audio.play();
```
Це забезпечує негайний фідбек користувачу навіть при фоновій вкладці.

## 📂 5. СТРУКТУРА ДАНИХ ТА МОДЕЛЕЙ (DATA SCHEMA)

### 5.1. PetReport Model
Ключове поле: `isReunited`. 
- Коли `isReunited = false`, оголошення активне і відображається на мапі.
- Коли `isReunited = true`, спрацьовує CSS-тригер, що додає "святкову" золоту рамку та переміщує об'єкт у розділ Success Stories.

### 5.2. User Model
Зберігає контактні дані. Поле `phoneNumber` є обов'язковим для успішної реуніфікації, оскільки чат є першим етапом, а прямий дзвінок — другим.

## 📂 6. ОГЛЯД ФАЙЛОВОЇ СТРУКТУРИ

### 📂 Backend
- **`src/index.ts`:** Точка входу. Налаштування Express та Socket.io сервера.
- **`src/config/database.ts`:** Конфігурація підключення до PostgreSQL через пул з'єднань.
- **`src/config/ai.ts`:** (Critical) Складна логіка взаємодії з Google Gemini, керування чергами та мовна адаптація.
- **`src/routes/reports.ts`:** Обробка мультимедійних даних (Multer), геокодування (Nominatim) та CRUD операції.
- **`src/services/matching.ts`:** (Critical) Алгоритм ранжування кандидатів на основі векторної близькості.

### 📂 Frontend
- **`src/components/Common/PetCard.tsx`:** Універсальний візуальний компонент з підтримкою станів (Lost, Found, Reunited).
- **`src/components/LostPawsForm.tsx`:** Найскладніша форма в додатку. Містить логіку реверсивного геокодування: клік по мапі -> запит до API -> заповнення адреси.
- **`src/i18n/i18n.ts`:** Централізоване сховище перекладів. Жоден рядок тексту не є жорстко закодованим (hardcoded).

## 🚀 7. ПОВНЕ КЕРІВНИЦТВО ІЗ ЗАПУСКУ (DETAILED SETUP)

### 7.1. Підготовка середовища
1.  **PostgreSQL:** Створіть базу даних `lost_paws_db`. Переконайтеся, що порт 5432 відкритий.
2.  **Google AI Key:** Отримайте ключ у [Google AI Studio](https://aistudio.google.com/app/apikey). Модель Gemini 2.5 Flash є безкоштовною.

### 7.2. Налаштування Бекенду (Backend)
```bash
cd backend
npm install
```
Створіть файл `.env`:
```env
PORT=8080
DB_NAME=lost_paws_db
DB_USER=postgres
DB_PASSWORD=ваш_пароль
DB_HOST=localhost
GEMINI_API_KEY=ваш_ключ
JWT_SECRET=фраза_для_захисту
FRONTEND_URL=http://localhost:3005
```
**Запуск:**
- `npm run seed` — (Важливо!) Створить тестових користувачів, тварин та ШІ-вектори.
- `npm start` — Запустить сервер. Ви побачите `Database synced`.

### 7.3. Налаштування Фронтенду (Frontend)
```bash
cd frontend
npm install --legacy-peer-deps
```
Створіть файл `.env`:
```env
REACT_APP_API_URL=http://localhost:8080/api
```
**Запуск:**
- `npm start` — Запустить сайт на `http://localhost:3005`.

## 📋 8. ПОЯСНЕННЯ КЛЮЧОВОГО КОДУ (FOR PRESENTATION)

### 8.1. Динамічне розпізнавання локації
Ми використовуємо Nominatim API для перетворення кліку на мапі в людську адресу. Ми обробляємо дані так, щоб залишити лише місто та вулицю:
```javascript
const city = addr.city || addr.town || addr.village;
const street = addr.road || addr.street;
const formatted = `${city}, ${street}`;
```

### 8.2. Робота з іменами для знайдених тварин
Якщо статус `found`, форма приховує поле імені. На бекенді спрацьовує логіка:
`petName: petName || 'Unknown'`. Це дозволяє уникнути помилок валідації БД, коли ім'я тварини невідоме.

### 8.3. Захист від помилок ШІ (Cascading AI)
Код у `src/config/ai.ts` використовує "fallback" механізм. Якщо одна модель недоступна, система миттєво пробує іншу, що забезпечує безперебійність сервісу.
